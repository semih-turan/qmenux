## Authority and behavior

OperatorApplicationReview is an internal provider with list, beginReject, finishReject and reject. List requires actual signed Access, ACTIVE PLATFORM_ADMIN, current browser session/stored CSRF and browser-bound MFA. UUID cursor pagination defaults20/max100 and returns pending-only minimal application projections; unsubmitted drafts, applicant identity and private review metadata are excluded. No controller/BFF/UI registers privileged review operations yet. Existing operator flags/Preview/TLS and named route gates remain.

Rejection requires target application UUID plus closed {revision,reason,requestId}. Reason is trimmed, single-line, nonempty/max1000 UTF-16 units; revision1..2147483646 and canonical UUID request. The server selects tenant:reject, derives payloadHash from UTF-8 revision:reason, and binds target/request/payload with the existing separate step-up ceremony. The SQL contract derives the identical operation digest itself. Quotes, colons, accented/supplementary characters are covered with a real native signature; browser-selected hashes/actors/statuses cannot substitute.

reject first looks up an already recorded decision for the current verified operator/request. Exact same target/original revision/normalized reason returns the immutable decision without requiring another proof; changed payload or target409. The authenticated replay checks current session/MFA again and grants no new authority. A new decision consumes the bound step-up and locks the application in the same database transaction. Only PENDING_APPROVAL at the expected revision may become REJECTED; draft/already decided/stale409 and missing404. Revision increments once, reviewedAt is server-owned, and verified operator UUID/request/reason are recorded atomically with old/new OPERATOR audit. Concurrent identical retries converge on one recorded result; a lost proof race may perform a bounded read-only replay lookup, never an automatic write retry.

The decision creates no tenant, membership, approval or license, and does not suspend the applicant identity. REJECTED is terminal for this application; applicant edit cannot reopen it. Existing applicant list/create-idempotency/submit replay return the authoritative REJECTED state. The existing admin BFF/parser/screen accept that state and show only generic rejection/no-access wording, including stale submit/create retries. Internal reason/operator/request metadata is not returned to applicants. Another explicit new draft remains governed by existing create behavior; duplicate-business/appeal/reapplication/abuse policy still needs review and no automated reopening is added.
